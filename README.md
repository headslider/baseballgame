## 10. 問題データの基本ルール

### 10.1 ID

- `id` は重複不可。
- `id` は間違いプレイチェックの照合キーでもある。
- 既存問題の意味を大きく変える場合は、履歴・影響範囲を確認する。
- 削除は極力避け、停止や非表示で対応する。

### 10.2 type

| type | 内容 |
| --- | --- |
| `attack` | 攻撃判断 |
| `defense` | 守備判断 |
| `basic` | 基本動作 |

### 10.3 outs / outs_scope

- `attack` / `defense` は `outs` または `outs_scope` を必須とする。
- `basic` は `outs` 必須対象外。
- `outs_scope: "common"` は0/1/2アウトすべてで使える共通問題を表す。
- `outs` 未設定かつ `outs_scope` なしの未監査問題は出題候補外とする。
- `outs` は数値 `0` / `1` / `2` を基本とする。
- `outs` と `outs_scope: "common"` を同時指定しない。

### 10.4 visual

描画に影響する項目は空欄にしないでください。

- `visual.batter_runner`
- `visual.ball_path`
- `visual.runners`
- `visual.holder`
- `visual.target_position`
- `visual.play`

特に `visual.batter_runner` は true / false を明示します。  
キャッチャーフライなど打者走者を出さない問題では `false` を明示します。

## 11. 学年制限ルール

出題候補は基本的に「選択学年 + 1」までを許可します。  
ただし、`min_grade` / `max_grade` がある場合はそれを優先します。

| 設定 | 出題対象 |
| --- | --- |
| `min_grade: 5` | 5年生以上のみ |
| `max_grade: 4` | 4年生まで |
| `max_grade: 5` | 5年生まで |
| `min_grade: 5, max_grade: 5` | 5年生のみ |

重要: `max_grade` は「選択学年」に対する上限です。  
`grade + 1` の上限ではありません。

### 11.1 高学年向けに制限すべき問題

以下の系統は低学年に出さないよう `min_grade` を確認します。

- スクイズ関連
- クリーンナップ関連
- D008のような難しい守備判断
- 高度な連携判断
- 高度な戦術判断

### 11.2 高学年に不要な問題

以下の系統は高学年に出しすぎないよう `max_grade` を確認します。

- 振り逃げの基礎問題
- 低学年キャッチャー基礎
- 低学年外野基礎
- 低学年向けフライ・ゴロ基本動作
- 3フィートライン基礎問題

### 11.3 v822時点で重要な学年制限

- HIGH振り逃げ系6件: `max_grade: 4`
- low_grade系13件: `max_grade: 5`
- A256: `max_grade: 4`

## 13. 野球判断・問題表現の重要ルール

### 13.1 外野返球

外野返球は、無理な本塁遠投を正解にしないことを基本にします。

基本方針:

- 中継へ素早く返球する。
- 中継へ低く正確に返球する。
- 捕球後すぐにステップして返球する。
- 状況によっては二塁進塁を防ぐ返球を優先する。
- 本塁で無理な走者を刺しに行くより、打者走者の進塁阻止を優先する場面がある。

### 13.2 外野捕球

- 「顔(おでこ)の横でとる」に統一。
- 「おでこの横」「顔(おでこ)のよこ」は使わない。
- 右後方フライは「右足を後ろに引き身体を横にして素早く後ろに下がる」。
- 左後方フライは「左足を後ろに引き身体を横にして素早く後ろに下がる」。
- グローブを早めに出す選択肢は誤答候補として使うが、露骨な説明文にしない。

### 13.3 トンネル

外野トンネル問題では、正解は以下の系統にする。

- ボールをすぐに追いかけて拾い、中継へ素早く返球する。

1点例:

- 慌てずボールを拾って確実に中継へ返す。

0点例:

- 本塁に急いで返球する。

### 13.4 3フィートライン・打者走者

- バッターではなく「打者走者」と表現する。
- 一塁後半は3フィートラインの走路を走る。
- A256/A257/A261のような同系統問題は必ずまとめて確認する。
- A256の一塁側は「一塁線」。
- 三塁から本塁は「三塁線」。

### 13.5 表記統一

| NG | OK |
| --- | --- |
| ハーフウェー | ハーフウェイ |
| おでこの横 | 顔(おでこ)の横 |
| 顔(おでこ)のよこ | 顔(おでこ)の横 |
| ファウルライン（一塁側文脈） | 一塁線 |
| ファウルライン（三塁側文脈） | 三塁線 |

### 13.6 ネガティブすぎる選択肢

選択肢は、最初から間違いだと分かる説明を避けます。  
ただし、短く自然な行動表現にすること。

修正済み例:

| 旧 | 新 |
| --- | --- |
| 捕球後の返球準備が遅れる | 捕球後ボールを確認する |
| ランナーだけを見る | 走者を確認してから打球を見る |
| グローブを最初から出して追いかける | グローブを早めに出して追いかける |
| 本塁へ遠投する | 本塁へ返球する |
| その場で待つ | その場で次のプレイを待つ |
| 送球だけを考えておく | 捕球後どこに送球するか考える |

## 14. 出題ロジックの重要仕様

### 14.1 アウト順

攻撃・守備の問題は、ランダム抽出後にアウトカウント順に並ぶことを目的とします。

- 0アウト
- 1アウト
- 2アウト

の流れで出題されるようにします。

### 14.2 common問題

`outs_scope: "common"` の問題は0/1/2アウトすべての候補になります。  
ただし、未監査のouts空欄問題をcommon扱いしてはいけません。

### 14.3 同一ゲーム内重複

同一ゲーム内で同じ問題IDが重複しないようにします。  
候補不足が発生した場合も、できるだけ未使用IDを優先します。

### 14.4 守備問題数チェック

管理画面の問題管理には、問題一覧の下、問題CSV管理の上に「守備問題数チェック」を表示します。

確認する内容:

- 学年
- 守備位置
- 0アウト / 1アウト / 2アウト
- 0件警告
- 3件未満注意

## 15. 間違いプレイチェック仕様

間違いプレイチェックは、0点・1点だった問題をあとから確認できる復習機能です。

### 15.1 記録

- 0点・1点を記録する。
- 管理者モード中でも記録する。
- プレイヤーIDに紐づける。
- 既存の `scores/mistake_review.json` は消さない。

### 15.2 表示

問題更新後も、保存時の古いスナップショットだけで表示しません。

- 問題IDが現在も存在する場合、最新の問題文・正解・アドバイスで表示する。
- ユーザーが過去に選んだ選択肢は「前回の選択」として表示する。
- 問題が更新されている場合は「更新済み」表示を出す。
- 問題が削除・停止された場合は「更新または停止された問題」として扱う。

### 15.3 ランナー表示

間違いプレイチェックでは、唐突に「一塁二塁」と表示しない。

- `ランナーは一塁・二塁。`
- `ランナー：一・二塁`
- 攻撃問題で自分がランナーの場合は `あなたは一塁ランナーです` のように表示する。

### 16.1 PWAインストール案内

### 16.2 PWA管理者モード

## 17. 管理画面運用メモ

管理画面は `admin.html` から `api/admin_api.php` にアクセスして操作します。

主な管理対象:

- お知らせ通知
- ID管理
- ユーザー管理
- 問題管理
- 要望管理
- ユーザー分析
- アクセス解析・データ解析
- バージョン管理
- ログ

問題管理では、以下をセットで確認します。

- 問題一覧
- 問題編集
- CSVエクスポート
- CSVインポート
- 問題バックアップ
- 問題バージョン
- 守備問題数チェック

### 17.1 問題管理の必須チェック

管理画面・CSVインポートでは以下を必須チェックします。

- `attack` / `defense` は `outs` または `outs_scope` が必要。
- `basic` はouts必須対象外。
- `visual.batter_runner` はtrue/falseを明示。
- `visual.ball_path` は空欄にしない。
- scoreは3点・1点・0点を揃える。
- 各ポジションの `choices_by_position` にscore=3が1つだけ存在すること。

## 18. バージョン管理運用

管理画面の「バージョン追加・編集」は、更新履歴をユーザー画面に表示するための機能です。  
PWA通知とは別です。

### 18.1 内部バージョンとcache_version

管理画面の内部バージョンとcache_versionは、原則として `version.json` から自動入力される読み取り専用欄です。

手入力しないでください。

### 18.2 リリース履歴

本番反映後に、管理画面から登録します。

ユーザー向けには短く、管理者メモには詳細を入れます。

例:

```text
問題の出題順、外野守備問題、間違いプレイチェック機能を改善しました。
```

### 18.3 お知らせ通知

お知らせ通知は、バージョン履歴登録とは別に送信します。  
本番反映・動作確認後に送信してください。

## 20. 障害対応の初動

| 症状 | 初動 |
| --- | --- |
| 画面が古い | PWA/ブラウザキャッシュ、`service-worker.js`、`version.json` を確認 |
| PWAだけ挙動が違う | Service Worker、Cache Storage、クエリ付きapp.js/cssを確認 |
| ゲーム開始できない | `data/questions.json`、問題取得API、PHPエラーを確認 |
| スコア保存不可 | `api/save_score.php`、`scores/score_log.csv` の権限とバックアップを確認 |
| ランキングが出ない | `api/get_ranking.php`、`scores/score_log.csv` を確認 |
| 間違い履歴が出ない | `scores/mistake_review.json`、`assets/app.js`、管理者モード設定を確認 |
| 問題内容が違う | 問題IDで `data/questions.json` を確認し、同系統問題も一括監査 |
| 招待ID/管理者IDボタンがおかしい | `scores/issue_link_settings.json`、`api/issue_link_status.php`、PWA manifestを確認 |
| 通知が届かない | Push購読、`vendor/`、通知履歴、ブラウザ権限を確認 |

## 23. 最重要ルール

- `v822-production` を本番安定版として扱う。
- `scores/` と `requests/` は本番運用データ。変更・削除・初期化しない。
- PWA更新時は `index.html`、`service-worker.js`、`version.json` の整合性を必ず確認する。
- `scores/release_versions.json` は原則として管理画面経由で更新する。
- 問題を1問だけ直して終わらせない。同系統問題を必ず横断監査する。
- `min_grade` / `max_grade` を必ず確認する。
- `outs` / `outs_scope` を必ず確認する。
- `questions.json` をService Workerに入れない。
- 直接公開保護を維持する。
- 判断に迷ったら、Codexは勝手に進めずユーザーに確認する。
